# Experiment log

Every number in the paper traces to a record here plus the raw artefacts under
`results/`. For the Kaggle-style full GBDT sweep this script embeds the search grid and reports results for every listed value. All benchmark evaluations use native per-problem scoring.
- Experiment ID scheme: `<MODEL>-SPX-<FOLD>-S<SEED>`
- Artefacts: `results/raw/kronos_pred.parquet`, `windows_*/w_fold*_seed*.parquet`,
  `results/processed/daily_net.parquet`, `results/tables/*.csv`
- Machine-readable per-run log: `experiment_log.jsonl` (one JSON object per run)

## Traceability rule

`results/tables/*.csv` are generated by `code/statistics/generate_tables.py`
from `results/processed/*` and `results/raw/*`. `paper/tables/*.tex` are
generated from those CSVs by `code/statistics/to_latex.py`. The paper `\input`s
the fragments, so no experimental value appears as a literal in the `.tex`
source. Re-running `experiments/run_all.py` regenerates the whole chain.

## Failed and discarded runs

Discarded exploratory work is recorded here rather than hidden, because silent
pruning is a form of selection bias:

- An early Kronos build used a context window ending at `t-2`, discarding one
  day of signal. Detected by re-reading the window slice and corrected; the
  affected partial output was deleted and regenerated.
- An early RL implementation fed the environment a transposed observation
  tensor `(W, N, F)` instead of `(N, W, F)`; it raised a broadcast error rather
  than training silently, and was fixed before any result was produced.
- An early cost-sensitivity run crashed when one of the baseline long-only arms
  produced a weight matrix whose columns did not align with the return panel.
  Fixed by reindexing every arm onto the common column set.
- The initial RL budget (10 PPO epochs, rollout 24, 400 steps) could not finish
  22 folds inside the session budget; it was reduced and the reduction is
  disclosed as deviation D5 rather than presented as the source configuration.
